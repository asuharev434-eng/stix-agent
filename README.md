# STIX Agent

Нативный локальный ИИ-агент для macOS 14+ на SwiftUI. Помогает с небольшими задачами в коде, файлами и папками, терминалом, изображениями и MCP-подключениями. Чаты и память хранятся на вашем Mac; аккаунт STIX не нужен.

**Что умеет:** вести чаты с выбором локальной модели, выполнять файловые и терминальные задачи с управляемыми разрешениями, генерировать и редактировать изображения встроенной Core ML моделью или через локальный ComfyUI, подключать MCP и API, сохранять локальную память и историю. В интерфейсе есть очередь задач, прогресс, уточнения и просмотр изменений файлов.

Кнопка создания чата предлагает обычный агентный чат и **чистый чат** (`⌘⌥N`). Чистый чат начинается с 0 контекста: без системных инструкций, памяти, скиллов и инструментов; модель получает только сообщения этой переписки. Для действий с файлами и `/image` используйте обычный чат. Новый чат с выбранной папкой (`⌘⇧N`) получает имя этой папки.

> **Предварительная версия для Apple Silicon.** Автономная сборка включает Qwen3 4B, Core ML Stable Diffusion 1.5 и движки для импортированных GGUF, MLX и SDXL. LM Studio, Bionic и ComfyUI не требуются для этих локальных моделей. Перед переносом на другой Mac скопируйте импортированные модели из `~/Library/Application Support/STIX Agent/Models`; веса пользовательских моделей не публикуются в GitHub.

В исходном коде есть **экспериментальная автономная сборка**: llama.cpp/Metal для GGUF, MLX Swift для Qwen3.5/GPT-OSS, мультимодальный llama.cpp для Gemma 4, Core ML Stable Diffusion 1.5 и stable-diffusion.cpp/Metal для SDXL `.safetensors`. Модели импортируются в хранилище приложения. Точная правка объектов на проверенных SDXL моделях остаётся ограничением качества; пользовательские ComfyUI-workflow не переносятся автоматически. Команда сборки, хеши и результаты испытаний описаны в [инструкции для автономной сборки](docs/STANDALONE-BUILD.md). Указанный ниже опубликованный preview-DMG пока остаётся прежним; автономный релиз ещё не прошёл все проверки качества и нотариальное заверение.

[План самостоятельной версии со встроенными моделями и отдельной подготовкой к App Store](docs/superpowers/plans/2026-10-19-standalone-local-inference.md).

## Установка

1. Скачайте `STIX-Agent-0.8.3-macOS-arm64.dmg` на [странице релиза](https://github.com/asuharev434-eng/stix-agent/releases/tag/v0.8.3-preview.1).
2. Откройте DMG и перетащите **STIX Agent.app** в **Applications**.
3. Запустите приложение. При первом запуске macOS может предупредить о том, что эта предварительная сборка ещё не прошла нотариальное заверение Apple. Подробности и безопасный способ открытия — в [инструкции по установке](docs/INSTALL.md).
4. Подключите локальные модели. Для текстового чата запустите API LM Studio/Bionic; для `/image` запустите ComfyUI. Приложение попытается найти уже установленное окружение автоматически.

Сборка подписана Developer ID, но **пока не нотариально заверена**. Это не релиз Mac App Store. Для публичного распространения с обычным открытием без предупреждения требуется нотариальное заверение Apple. Исходный код и установщик доступны в этом репозитории; установщик не содержит модельных весов. Проверить контрольную сумму можно на странице релиза.

## Сборка из исходников

Понадобятся Xcode Command Line Tools или Xcode. Сборка устанавливается в `~/Applications/STIX Agent.app`.

```sh
./scripts/build-app.sh --install
open "$HOME/Applications/STIX Agent.app"
```

Нужны уже установленные локальные модели. Приложение обнаруживает API LM Studio/Bionic на localhost (включая порт из его локального конфига). На компьютере разработки полный агентный цикл проверен с Qwen3.5 9B; требования к памяти зависят от модели. Список моделей обновляется в меню выбора модели в левой части поля ввода.

ComfyUI: используется работающий API `http://127.0.0.1:8188`. Если его нет, приложение может запустить существующую установку **Local SDXL** из Comfy Desktop, используя её Python и модели `~/ComfyUI-Shared`. Запуск на loopback, с `--offline --disable-all-custom-nodes`. Чужой процесс не завершается; собственный завершается при выходе из приложения. Для сторонних узлов запустите доверенную установку ComfyUI самостоятельно и задайте её локальный URL через чат. Никаких внешних серверов, загрузки моделей или деплоя приложение не требует.

## Работа

- Новый чат: `⌘N`; чат с папкой: `⌘⇧N`. Папка необязательна; без неё рабочий каталог — домашняя папка.
- Перетащите файлы/папку в чат или нажмите `+`. Текст, PDF и DOCX читаются локально, сканы и фото проходят OCR. Vision-модели получают уменьшенные изображения. Текстовая основная модель получает OCR и может вызвать vision-специалиста. Неподдерживаемые и слишком большие вложения остаются доступными по пути с явным сообщением об ограничении чтения.
- Return отправляет, Shift+Return добавляет строку. `⌘.` останавливает активную задачу.
- `/models` или «Настрой модели» открывает форму в чате: текст, код, анализ, vision и другие задачи. Можно назначить доступную локальную модель или вернуть «Автоматически». Назначения специалистов общие, основная модель не меняется. Подготовка промпта и модель ComfyUI задаются для текущего чата. Изменения сохраняются сразу; старая карточка показывает текущие назначения.
- Выбор текстовой модели находится внизу слева в поле ввода.
- `/image описание` показывает два выбора: текстовая модель для перевода/адаптации и встроенная SD 1.5, checkpoint SDXL или импортированный workflow для изображения. Языковая модель готовит JSON промпта с учётом архитектуры, затем запускается выбранный локальный движок. Если внешняя модель подготовки недоступна, приложение использует встроенную, когда она есть, и показывает фактически использованную модель в карточке. Выбор модели подготовки не меняет основную модель чата.
- `/theme dark`, `/theme light`, `/theme system` работают без модели. Можно написать «Включи тёмную тему в этом приложении».
- `/plugins`, `/connections`, `/permissions`, `/permissions reset`, `/help`.
- Прочие изменения — обычным сообщением: «Измени адрес ComfyUI на http://127.0.0.1:8189», «Подключи API сервиса…».

## Действия, вопросы, секреты

Файловые инструменты действуют автоматически. Запись сохраняет резервную копию; перемещение не перезаписывает назначение; удаление использует Корзину macOS. Кнопка отмены проверяет, что содержимое не изменилось после действия. Квитанции отмены сохраняются между запусками. Каталоги поддерживаются до 10000 объектов/512 МБ, деревья с symlink отклоняются. Чтение — UTF-8 до1МБ, вывод ограничен.

Каждая новая произвольная команда терминала запрашивает разрешение: надёжно определить все побочные эффекты shell-команды по её тексту нельзя. «Для этой задачи» разрешает дальнейшие команды в её рабочей папке до завершения; «Всегда» относится к точной команде с аргументами. MCP и HTTP-запросы имеют отдельные точные разрешения. Постоянные разрешения отзываются сообщением. Команды с дочерними процессами получают таймаут и завершаются группой; фоновые процессы команд не сохраняются. Терминальные изменения не имеют гарантированного отката.

Вопрос агента — карточка с вариантами и свободным ответом. Секрет — отдельное защищённое поле; обычный ввод чата на этот момент отключён. Значение хранится в **macOS Keychain**, не попадает в JSON истории или контекст модели. Известные секреты и их base64/URL-представления скрываются в результатах, частичные совпадения удерживаются при streaming. Намеренно преобразованные неизвестным способом секреты не могут быть распознаны универсально; не поручайте модели читать системные хранилища секретов.

## API и плагины

Напишите название, базовый URL и способ авторизации API. Поддерживаются bearer, отдельный header, basic и без авторизации. Ключ вводится только в защищённой форме. Запросы исполняются приложением с подстановкой ключа, без редиректов и выхода за origin/base path. Внешние подключения требуют HTTPS. До явного подключения и поручения никакие пользовательские файлы наружу не отправляются.

Рядом с данными подключений создаётся `~/Library/Application Support/STIX Agent/Documentation/<connection-id>/`. Положите туда документацию. Агент видит путь и может читать её. Из чата можно заменить ключ или удалить подключение с ключом; документация при удалении подключения сохраняется.

MCP: локальный stdio executable + массив аргументов или HTTP URL. Первое включение подтверждается. Поддерживается protocol `2025-03-26`, tools/list и tools/call. HTTP требует совместимого Streamable HTTP endpoint; SSE transport старого образца и sampling не реализованы. OAuth REST-подключений поддерживает public-client Authorization Code + PKCE, redirect `stixagent://oauth/callback`, HTTPS endpoints и refresh-токены в Keychain. Секреты плагина задаются через защищённый ввод и ссылки credential_id → environment; значения не сохраняются в конфиге. Аргументы плагина — не место для ключей.

## Изображения и артефакты

Стандартный профиль: SDXL checkpoint, 1024×1024,20 шагов. Другие архитектуры подключаются импортом ComfyUI **API workflow JSON** через чат. В input-значениях нужны точный `{{prompt}}`, опционально `{{seed}}` и `{{checkpoint}}`. Workflow должен содержать SaveImage; префикс сохранения принудительно STIXAgent. Необходимые модели/узлы должны уже быть установлены. В ComfyUI, запущенном самим приложением, после генерации освобождается память модели, если очередь пуста. Отмена удаляет свой prompt из очереди; активный prompt прерывается только после проверки текущей очереди (API ComfyUI имеет глобальный interrupt).

Markdown, код с копированием, фото, файлы с Quick Look, SVG, Mermaid и интерактивные HTML-дашборды отображаются в ответах. Mermaid10.9.3 поставляется локально по MIT. HTML выполняется в отдельном WebKit с CSP и блокировкой URL без native bridge, cookies, файлов и сети. Открытие артефакта во внешнем приложении — отдельное пользовательское действие.

## Данные и права

`~/Library/Application Support/STIX Agent/`: `state.json`, предыдущая версия, `Attachments`, `Backups`, `Documentation`, `Workflows`, локальный журнал ComfyUI. Запись состояния атомарная; при повреждении исходный файл не перезаписывается. Прерванные действия отмечаются и не повторяются автоматически.

Первый запуск показывает карточку прав. macOS отдельно выдаёт доступ к папкам, Full Disk Access, Accessibility и Automation. Приложение не меняет TCC и не получает root заранее. На этом Mac настроена подпись установленным Developer ID Application: идентификатор сертификата хранится в локальном .signing-identity, приватный ключ остаётся в Keychain. При отсутствии настроенной identity сборка использует ad-hoc. Для распространения другим людям отдельно нужна notarization; локальная сборка не обращается к сервису notarization или timestamp.

## Проверка

```sh
swift test
STIX_AGENT_LIVE=1 swift test --filter LiveIntegrationTests
./scripts/build-app.sh --install
```

Live-тесты обращаются только к локальным API1235/8188, создают временный файл через настоящий агентный цикл и PNG через SDXL. Они не используют платные API, ключи, GitHub или внешнюю инфраструктуру.

## Возможности версии 0.3

- Поиск по названиям и сообщениям; закрепление, переименование, экспорт Markdown. Редактирование/повтор создаёт отдельную ветку и сохраняет оригинал.
- Очередь задач, пауза, отмена, продолжение. После перезапуска задачи становятся прерванными; продолжение — явное действие пользователя. Модель проверяет состояние перед продолжением; произвольный терминал и внешние действия не имеют транзакционного восстановления.
- `preview_changes` показывает diff и массовые перемещения; `apply_changes` проверяет актуальность, сохраняет журнал и откатывает выполненную часть при ошибке. Кнопка «Отменить файлы» отменяет доступные файловые квитанции задачи в обратном порядке, останавливаясь при конфликте.
- Общая память через «Запомни…» / «Забудь…», без секретов. Длинный контекст сокращается до полных групп инструментов с помеченными фрагментами опущенной истории.
- Основная модель может вызвать установленного локального специалиста `delegate_model`, получить анализ и проверить его. У специалиста нет инструментов и рекурсивного делегирования. Роли coding/reasoning/vision/writing/general настраиваются в чате; основная модель сохраняется. Возможности по названиям моделей помечаются как предположения.
- Пять ступеней уточнений в поле ввода: лимиты 0/1/3/6/12 вопросов на задачу. По умолчанию один вопрос. Разрешения и защищённый ввод считаются отдельно.
- Thinking показывает только фактически получаемый поток reasoning модели и автоматически скрывается после задачи. Поток не сохраняется в истории. Поддержка зависит от модели/API.
- «Увеличь шрифт до 18», отступы, язык image-промпта — через сообщения. `font_size` 11–24; `spacing` 12–48; `image_prompt_language` auto/en/ru/zh/ja.
- Кнопка «Редактировать» у картинки прикладывает исходник. Можно написать «измени последнюю картинку» — `generate_image` использует input_image=last. Оригинал сохраняется. Маска — локальный PNG/JPEG/WebP: белое меняется, чёрное сохраняется. Для точной маски прикрепите готовый файл; рисование маски в приложении пока не предусмотрено.
- Параметры `/image`: `--input last`, `--mask /absolute/mask.png`, `--size 1024x1024`, `--steps 20`, `--seed 42`, `--cfg 7`, `--denoise 0.5`, `--negative "..."`, `--count 2`. `--resize-only` меняет размер без diffusion и языковой модели. Для custom workflow опции требуют соответствующих placeholders.
- Приложения: bounded Accessibility snapshot и click/fill/scroll, локальные снимки окон/экрана. Safari/Chrome: вкладки, текст страницы, открыть/click/fill; без произвольного JavaScript. Требуются отдельные права macOS; DOM браузера требует Allow JavaScript from Apple Events. Защищённые поля недоступны модели. Старые snapshot нельзя использовать повторно.
- `run_shell` принимает только ссылки на защищённые секреты через environment_json. Плагинам секреты передаются через configure_plugin_environment после подтверждения. OAuth-провайдеры требуют собственной регистрации публичного клиента; аккаунты и API-ключи автоматически не создаются.

Документы: до 8 вложений, PDF до 40 страниц, UTF-8/OCR до 200000 символов на документ; DOCX — основной текст без сохранения сложной вёрстки. Точность OCR зависит от качества исходника.


### Поиск и управление задачами

`web_search` получает публичные результаты DuckDuckGo HTML без API-ключа. `read_web_page` читает ограниченный объём текста публичной страницы без JavaScript и cookies. Запрос выходит в интернет напрямую к DuckDuckGo; своего сервера нет. При капче или ограничении частоты показывается ошибка. Локальные адреса и известные секреты запрещены. Через чат можно отключить поиск (`set_preference web_search_enabled=false`).

Для выполняемой задачи показываются этап, время и число завершённых действий. При получении sampler-событий ComfyUI выводится настоящий процент по шагам именно своего prompt_id; при неизвестном объёме работы — движущаяся полоса без вымышленного процента. Для очереди доступны редактирование, перемещение, удаление и применение сообщения к текущей задаче. Return ставит отдельную задачу в очередь: ожидающее сообщение видно в списке задач и появляется в переписке только при запуске этой задачи. «Уточнить текущую» или ⌘Return передаёт корректировку. Исполнитель учитывает её перед следующим действием, отклоняет устаревшее подтверждение и сохраняет уточнение в истории. Уже завершённые действия не отменяются сами. `list_tasks`, `manage_task`, `queue_task` доступны основной модели. При закрытом приложении задачи не выполняются; ещё не начатая очередь запускается после открытия приложения, а прерванную задачу нужно продолжить явно.

Пассивная диагностика системных прав: `STIXAgent --capabilities-json` из подписанного app bundle. Диагностика не запрашивает и не выдаёт права.

Проверки через основную модель, отдельно от пользовательских чатов: `STIX_AGENT_CAPABILITY_AUDIT=1 swift test --filter LiveCapabilityTests` (не запускайте одновременно с собственными генерациями; image-тест пропускается при занятой очереди). Эти проверки действительно обращаются к установленным моделям, DuckDuckGo и ComfyUI; отчёты сохраняются в `dist/capability-*.json`. Обычный `swift test` не запускает локальные модели.

При вводе `/` над полем появляется меню команд и подключённых плагинов. ↑/↓ выбирают пункт, Enter открывает команду или вставляет её префикс; Tab только дополняет ввод, Esc закрывает подсказки. Для плагина укажите задачу после `/plugin/<id> `. Панель задач сворачивается по заголовку. Крестик на завершённой карточке скрывает её, крестик в заголовке скрывает завершённые карточки чата. `/tasks` разворачивает панель и возвращает закрытые карточки. Скрытие сохраняется после перезапуска и не удаляет историю, файлы или возможность отката.

При повторном запросе генерации с тем же описанием и источником внутри текущей задачи возвращается уже полученный результат, затем модель получает запрос краткого текстового итога. Маска, negative, seed и denoise различают инструкции; изменение размера без генерации не ограничивается этим механизмом. Новое сообщение или корректировка открывает новый цикл. Это предотвращает бесконечные повторные img2img-вызовы слабой моделью.

### Скиллы, память и надёжность (0.4)

- `/skills`: локальные папки `Skills/<name>/SKILL.md`, импорт, редактирование с историей версий, включение/отключение. Предустановлен `skill-creator`; вызов `/skill/skill-creator описание` или `$skill-creator описание`. Агент видит метаданные и читает подходящую инструкцию по необходимости. Скиллы не расширяют права инструментов.
- `/memory`: посмотреть, изменить и удалить предпочтения, папки и договорённости. `/search запрос`: поиск сообщений с переходом к результату. Черновики сохраняются отдельно в каждом чате.
- `/diagnostics`: локальная проверка LM Studio, ComfyUI, очередей, памяти и разрешений без передачи переписки/ключей и без загрузки моделей.
- Кнопка микрофона: только распознавание на устройстве, текст сначала в черновик. По умолчанию русский; смена языка через чат (`voice_language`, например `en-US`). Требуются системные разрешения и поддержка языка локальным Speech.
- «Редактировать» у картинки: кисть и ластик маски, сила изменений, сравнение до/после, изображения из истории чата. Новый результат сохраняется отдельно.
- «Изменения файла»: diff и до/после по сохранённой квитанции; можно отменить отдельный файл или все доступные изменения задачи. Изменённые снаружи файлы не перезаписываются откатом.
- Журнал повторных вызовов переживает продолжение задачи, прерванные операции требуют проверки состояния. Таймауты отвечают на отсутствие полезного прогресса, а не SSE keepalive. Длинная история сокращается с сохранением последних запросов, пар инструментов и обозначенных дословных фрагментов; полная история остаётся локально.
- При смене моделей native LM Studio API выгружает только модели, которые загрузил STIX в текущем процессе. Уже загруженные пользователем экземпляры сохраняются. При неподдерживаемом API автоматическая выгрузка пропускается.
