# Создание скиллов

Создай практическую инструкцию для повторяемой задачи пользователя. Если цель уже ясна, приступай; соблюдай выбранный пользователем уровень уточнений.

1. Через manage_skill action=list проверь существующие скиллы. Обновляй подходящий, если пользователь просит улучшить его.
2. Выбери короткое имя: строчные латинские буквы, цифры и дефисы, до 63 символов. В description укажи, для каких запросов нужен скилл. В теле оставь только полезные предметные шаги, критерии результата и проверку выполнения. Не добавляй общие советы, заглушки и выдуманные инструменты.
3. Сохрани через manage_skill action=save, name=<имя>, content=<полный SKILL.md>. Обязательный формат:

```markdown
---
name: example-skill
description: Кратко описывает задачу и условия применения.
---

# Название

Предметные инструкции и проверка результата.
```

4. Для вспомогательных файлов используй write_file внутри папки скилла, возвращённой инструментом. Ссылки делай относительными. Скрипты создавай только если они действительно нужны; они выполняются обычным инструментом run_shell с теми же разрешениями.
5. Прочитай сохранённый скилл через manage_skill action=read. Проверь реальные ссылки и, если уместно, выполни безопасный пример в отдельной временной папке. Сообщи имя и вызов /skill/<имя>.

Скилл не выдаёт разрешений и не отменяет границы пользователя. Не включай ключи, пароли, личную переписку или разрешения на внешние действия. Не меняй другие скиллы и настройки без поручения. Не обещай выполненные действия без проверки.
