# STIX Agent: самостоятельный локальный инференс — план внедрения

## Статус на 19 октября 2026

В ветке `codex/standalone-inference` реализованы общие интерфейсы, llama.cpp/Metal, встроенная Qwen3 4B, импорт GGUF, Core ML Stable Diffusion с SafetyChecker, генерация и img2img, а также запуск без обязательных LM Studio/ComfyUI. На этом Mac установлена подписанная сборка 0.9.4. Полный Swift-набор: 273 теста, 18 пропущены, 0 ошибок. В живом чате проверены текст, последовательные файловые инструменты, `/image`, правка и сохранение результата после перезапуска; история существующих чатов и вложения сверены с резервной копией.

**План не закрыт.** Встроенная модель не справилась с точной правкой цвета объекта; нет подтверждённой минимальной конфигурации Mac, замеров RAM/энергопотребления для графического движка, нотариального заверения и проверки Gatekeeper на чистом устройстве. Распространение Apple-конверсии SD1.5 требует отдельной проверки условий и продуктовых ограничений карточки модели. Пункт 8 (sandbox, Xcode archive и App Review) не выполнен. Поэтому текущий DMG — локальный технический артефакт, а не публичный релиз или сборка App Store. Подробные результаты — в `docs/INFERENCE-MATRIX.md`.

> **Для исполнителя:** выполняйте задачи по порядку, отмечайте `- [x]` только после указанной проверки. Каждый этап должен оставлять работоспособную сборку; сохраняйте историю и память пользователя. Для выполнения по задачам используйте workflow `executing-plans` или `subagent-driven-development`, если делегирование отдельно разрешено.

**Цель:** STIX Agent запускается на чистом Mac без LM Studio и ComfyUI, сразу отвечает встроенной лёгкой текстовой моделью и генерирует/редактирует изображения встроенной моделью. Другие модели добавляются пользователем через выбор локального файла. Текущие интеграции остаются дополнительными.

**Архитектура:** чат, очередь, память и инструменты обращаются к двум внутренним интерфейсам инференса. Первый встроенный адаптер текста использует `llama.cpp` с Metal и GGUF; адаптер изображения использует нативный Core ML pipeline. `LMStudioClient` и `ComfyClient` остаются адаптерами совместимости, но не участвуют в первом запуске. Базовые веса лежат в подписанном app bundle; импортированные — в хранилище приложения.

**Стек:** SwiftUI, SwiftPM/Xcode, macOS 14+, Apple Silicon, Metal, Core ML. Точную ревизию движков и моделей закрепить после задач 1–2.

## Границы и решения до начала кода

- Сначала выпустить **самостоятельный подписанный DMG** с полным агентом. App Store — отдельный канал поставки: его sandbox и правила могут потребовать убрать или сузить `run_shell`, управление другими приложениями и браузером. Не обещать одинаковый набор инструментов до проверки задачи 8.
- Встроенная модель изображений отвечает за **генерацию и правки**. Анализ изображений требует vision-модели; он не появляется автоматически от наличия diffusion-модели. Для анализа сохранить импорт или подключение отдельной модели.
- «Сверхлёгкая» означает измеренные размер полного комплекта, память, задержку и приемлемое качество, а не название модели. Qwen3-1.7B — только кандидат для текстового испытания; image-checkpoint пока не выбран.
- Никаких автоматических скачиваний весов при первом запуске. Встроенные модели входят в сборку; дополнительную модель пользователь выбирает сам. Лицензии весов, конверсий и данных проверяются **для точных файлов и ревизий** до включения в релиз.
- История, scoped memory, ключи Keychain, вложения, очередь и прежние назначения моделей должны пережить обновление. Перед любой миграцией — проверенная локальная копия и тест восстановления.

### 2. Вынести общие интерфейсы без смены поведения

- [ ] Добавить `TextInferenceEngine` с `models`, потоковым `complete`, отменой, лимитом контекста и освобождением ресурсов; `ImageInferenceEngine` с `models`, `generate`, исходным изображением/маской, прогрессом и отменой. Использовать существующие `LMMessage`, `LMReply`, `ImageRequest` и `ToolDefinition`, не дублировать формат истории.
- [ ] Зафиксировать минимальный контракт в `Integrations/InferenceEngine.swift` до переноса вызовов:

```swift
enum ModelProvider: String, Codable, Sendable {
    case builtInText, builtInImage, lmStudio, comfyUI
}

struct ModelRef: Codable, Hashable, Sendable {
    let provider: ModelProvider
    let id: String
}

protocol TextInferenceEngine: Sendable {
    func models() async throws -> [ModelDescriptor]
    func contextLimit(for model: ModelRef) async throws -> Int?
    func complete(model: ModelRef, messages: [LMMessage], tools: [ToolDefinition],
                  onToken: @escaping @Sendable (String) async -> Void) async throws -> LMReply
}

protocol ImageInferenceEngine: Sendable {
    func models() async throws -> [ModelDescriptor]
    func generate(model: ModelRef, request: ImageRequest, outputDirectory: URL,
                  onStep: @escaping @Sendable (Int, Int) async -> Void) async throws -> [URL]
}
```

  Отмена идёт через `Task.cancel()`; конкретные адаптеры обязаны останавливать свою нативную работу или HTTP-запрос. Registry выбирает движок по `ModelRef.provider`; неизвестное значение при чтении сохранённых данных вызывает явную ошибку, исходные данные сохраняются.
- [ ] Добавить типизированный `ModelRef(provider, id)` и registry. Новые ID хранить с провайдером; старые строки `Chat.model`, `Chat.imageModel` и `modelRoles` читать через совместимый resolver, не переписывая их без транзакционной миграции.
- [ ] Обернуть нынешние `LMStudioClient` и `ComfyClient` в эти интерфейсы. Перевести вызовы из `AgentEngine.swift`, `ChatContext.swift`, `ModelOrchestrator.swift` и `ResultGallery.swift` на registry. Сохранить прежнее поведение при выборе внешнего провайдера.
- [ ] **Проверка:** сначала тест с fake-engine доказывает, что чат и `/image` используют выбранный интерфейс, что cancellation останавливает запрос и что старые ID читаются; затем `swift test` и живой прогон с имеющимися LM Studio/ComfyUI.

## Очерёдность и контрольные точки

`1 → 2 → 3 → 4` даёт самостоятельный текстовый агент. `3 → 5` добавляет изображения. `4 + 5 → 6 → 7` дают публичный DMG. Задача 8 начинается после архитектурного контракта из задачи 2, но выход в App Store зависит от успешной задачи 7 и отдельной sandbox-проверки.

**Ближайшая реализуемая часть:** задачи 1–3. Они дадут доказательство, что выбранная лёгкая модель действительно управляет инструментами; до этого фиксировать image-модель и обещать App Store-функциональность рано.

**Ожидаемое сопровождение:** один встроенный текстовый и один графический движок добавят нативные зависимости и крупные ресурсы, но снимут поддержку обязательных сторонних установок. Внешние адаптеры потребуют периодической проверки API, зато сохранят совместимость с уже установленными моделями. App Store-вариант добавит отдельную матрицу возможностей и тестов sandbox; это основной постоянный расход сопровождения.
