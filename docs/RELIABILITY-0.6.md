# STIX Agent 0.6.0 (12)

Local reliability and transparency update, 2026-10-19. SwiftUI/SwiftPM, existing system libraries only. No GitHub publication, deployment or external service was used.

## Delivered behavior

1. **Recovery.** Interrupted tasks keep their phase, completed-step count and receipts. The checklist button inspects current files without replaying operations. Continue performs that check before inference and includes its report in context. Existing durable tool-call history prevents identical mutation replay. An interrupted image submission cannot automatically generate again in the same resumed task: start a new requested generation after inspecting existing output/ComfyUI queue.
2. **File preview and undo.** A native card lists the exact planned moves, writes and Trash operations. Clicking Apply authorizes that plan, revalidates source/destination digests, creates a task and durable undo receipts, and checks results. Undo remains conflict-aware. Manual apply/undo requests and outcomes also enter model history so later conversation sees the changed state.
3. **Context inspection.** The context indicator opens a scrollable view of instructions, selected scoped memory, tools, summary and messages. Its snapshot is captured after the client's final context fitting. It is kept in RAM until the app closes. Image base64 is replaced by an image count in the viewer. The current budget estimate and last formed request are explicitly distinguished; a captured request does not prove server delivery.
4. **Memory versions.** Before/after revisions are committed in the same transaction as memory documents in Memory/history.jsonl. /memory exposes scoped history and restore. Restoration creates a new revision. Source/provenance is retained. Old entries and potentially different key:value facts in the same owner/category receive review hints; nothing rewrites them automatically. History is recoverable local data, so deleting an active entry does not erase its revisions.
5. **Corrections and queue.** Existing queued-message edit/reorder controls remain. /pause, /stop, «остановись» and «стоп» pause the running task. /skip, «пропусти этот шаг» and «пропусти это» suppress the next not-yet-executed tool call; they cannot undo an action already in progress. «сделай иначе: …», «вместо этого …» and /steer apply a correction. An obsolete approval is denied and replaced by the correction; protected secret input remains separate.
6. **Verification.** File mutations automatically check current state/digests. Python, JavaScript, JSON, sh/zsh writes also receive syntax checks; user script bodies are not executed by syntax validation. Generated images are decoded and dimensions checked. Shell exit/timeout and explicit verify_result evidence are recorded in task cards and passed to the main model. Missing runtimes or failed checks are reported. Actual behavioral tests still require a suitable run_shell test; syntax alone does not establish program correctness.
7. **Specialists.** Automatic assignments consider capability metadata/name hints, conservative parameter-size RAM estimates, physical RAM, free+inactive RAM and already-loaded models. User-configured assignments take priority. Known non-vision models reject image delegation. The chat shows which specialist was selected and why. Specialists have no tools; the main model stays selected and reviews their response. Weight size/memory and name-based capability estimates are explicitly heuristic.
8. **Doctor.** /doctor aliases the existing diagnostics workflow and reports local LM Studio/ComfyUI APIs, model/checkpoint availability, queues, RAM, disk space and macOS permissions with corrective instructions. It never loads a model, executes inference or prompts for permission itself.
