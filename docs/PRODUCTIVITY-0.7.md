# STIX Agent 0.7 — local productivity

All implementation, builds and verification stay on this Mac. No GitHub, deployment, cloud processing, account or telemetry was added. Custom MCP OAuth is a separate follow-up release.

## Available in chat

- `/workflows`: typed parameter forms and repeatable scenarios. Built-in photo preparation makes resized JPEG/PNG copies with per-file undo. Fixed steps accept exact typed `{{field}}` values, never interpolated shell strings. Optional skill-backed scenarios can run a prompt; a skill's bounded `form.json` adds a “Заполнить форму” button in `/skills`.
- `/automations`: daily and folder-change rules, enable/disable, local event history. A user LaunchAgent is installed only after a rule is enabled. It checks every 60 seconds in the logged-in Aqua session and can reopen the app in the background. It does not wake a sleeping or logged-out Mac. Daily catch-up runs at most once for the current day; folder watches baseline existing files and wait at least three seconds after a write. Ordinary approvals remain in effect. Durable event IDs deduplicate queue insertion after a crash.
- `/documents`: explicitly connected local folders, incremental hash-based PDF/DOCX/text extraction and search, exact PDF page citations and inline PDF preview. DOCX/text citations identify fragments, not invented pages. A disposable SQLite index can be rebuilt. Bounds: 1000 documents, 5000 objects per folder, supported document size limits. Source documents stay unchanged.
- `run_isolated`: Python/JavaScript/shell under macOS Seatbelt, network denied, only copied inputs and local runtime libraries readable, writes confined to private Outputs/Temp. Results are not published into the working folder until `publish_isolated_output` is reviewed. No unrestricted fallback if Seatbelt is unavailable. Limits: 120 seconds, eight inputs / 50 MB, 200 outputs / 100 MB; this is process isolation, not a VM or a disk quota.
- `/gallery`: actual output attachments across chats, source-chat links, thumbnail previews and search. New image generations retain their real prompt, model/workflow, seed and parameters. Repeat uses saved parameters; variant changes seed. Pixel identity depends on the installed ComfyUI workflow/runtime. Earlier images without a recorded recipe are labelled accordingly; existing image editing remains available in the original chat.
- `/resources`: automatic/economy/performance policy, available-memory estimate, macOS low-power/thermal state, release of model instances loaded by the agent. Economy defers background automation/indexing/backups, limits ordinary text output reserve to 2048 tokens and default image steps to 12; explicitly requested image parameters remain unchanged. Actual request phases replace an undifferentiated spinner.
- `/backups`: SHA-256-verified full snapshots outside the data root, portable regular attachments, disk copies, complete restore with staging/journal and retained previous data, or selected chat import as a new independent chat. Originals, drafts and memory remain intact. Old restored undo buttons are disabled on imported chats. Automatic snapshots run while the app is open, idle and not in economy; seven automatic snapshots retained, manual copies retained. Missing external files are recorded; project folders remain references.
- Protected credential transfer uses separate AES-GCM archives, PBKDF2-HMAC-SHA256 with 600000 rounds and a random salt. Passwords and values never enter chat/model history. Keychain contents are excluded from ordinary backups. Export/import requires explicit actions in a native secure form; failed writes attempt rollback and report any rollback failure.
- Global `⌃⌥Space` opens quick capture while the app is running. Selected text is read through Accessibility only when access is already granted; secure text fields are excluded. The clipboard is not changed. Finder can send files through Services → “Передать в STIX Agent”, which can launch the app. Capture may create a new chat or use the current one, and may open a draft or send immediately.

## Data compatibility

`Features/config.json` is an optional versioned extension of the existing transactional split store. Old stores load defaults; once the file is declared, a missing file fails closed instead of silently resetting configuration. Chats, scoped memory, receipts and attachments remain canonical. Search indexes are derived and excluded from backups. Existing Keychain IDs remain unchanged. Restore verifies every listed file and rejects unlisted files, symlinks and special files before replacing a data root.

## Validation

Evidence and installation details are appended after final verification. Synthetic tests and native QA use separate data roots and never run credential transfer against real keys.
