# STIX Agent 0.8 — custom MCP with OAuth

`/plugins` opens a live card in the chat. Enter the full HTTPS Streamable HTTP MCP endpoint, such as `https://stixapp.ru/mcp`, and select **Find OAuth parameters**. The client probes the MCP resource, reads protected-resource and authorization-server metadata, requires exact resource/issuer matching and PKCE S256, then shows declared scopes. Read-only scopes are selected by default; any server-required scopes remain selected. A pre-registered public client ID can be supplied; otherwise the app uses the advertised dynamic client registration endpoint after the user presses Connect.

The native macOS authentication session uses Authorization Code with PKCE S256 and the exact MCP `resource` parameter. Tokens are stored in Keychain under the plugin ID, refreshed when needed, and sent only as a bearer header to the configured HTTPS MCP URL. HTTP redirects are refused for token-bearing requests. No token or authorization code is recorded in chat or included in plugin configuration. Removing an OAuth plugin removes its Keychain token; encrypted credential export includes these tokens when the user explicitly exports credentials.

After authentication, the app initializes the MCP session and lists tools before enabling the plugin. Reconnecting preserves the previous configuration if authorization or initialization fails. Tool calls continue to use the app's action approval policy. HTTP 401 triggers at most one refresh/retry; another 401 asks for reconnection, and 403 asks for broader scopes. The app supports MCP protocol versions 2025-03-26, 2025-06-18, 2025-11-25, and 2026-07-28 when returned by the server.

This release also contains all local productivity features from [PRODUCTIVITY-0.7.md](PRODUCTIVITY-0.7.md). Existing chats, local memory, attachments, settings, and legacy stdio/HTTP plugins stay in place. No remote MCP user grant is created during installation: the account owner initiates the system OAuth window from the chat card.

Validation on this Mac: 243 XCTest cases passed; 12 opt-in environment tests were skipped. A separate signed QA bundle used its own synthetic data root. Its `/plugins` card remained scrollable above the composer. Read-only discovery against the example endpoint showed the real issuer and endpoints, selected `stix:read`, and left `stix:write`/`stix:admin` unselected. No dynamic registration or account OAuth consent was attempted during QA. The release bundle is signed as 0.8.0 (14) and passed `codesign --verify --deep --strict` before installation.
